# 需求时间只与创建有关

- 状态：已接受
- 日期：2026-09-14

## 背景

`updatedAt` 同时承担两个职责：它是需求目录的排序依据，也是卡片上显示的日期。此前管理器和插件 MCP 的每次写入都会把它刷成当前时间，于是改一个错别字、换一张图或调整标题，需求就会跳到目录最前面；整理存量需求时一批需求互相顶序，目录失去稳定顺序，卡片日期也不再反映创建时间。

## 决策

`createdAt` 与 `updatedAt` 都只在需求创建时写入，之后不再变化，所有写入路径只改内容：

- 管理器：状态、标题、正文，以及图示的新增、删除、改名、分组与排序。
- 插件 MCP：`complete_implemented_requirement` 与 `update_requirement_content` 保留目标需求已有的时间。

因此需求的目录位置与卡片日期都只反映创建，编辑不会让它跳到最前。`updatedAt` 不再是“最后修改时间”。

## 后果

目录顺序稳定，整理存量需求时不再互相顶序，卡片日期可以直接读作创建日。代价是无法再通过字段判断某条需求最近是否被改过，只能依赖文件差异或版本历史。历史数据里已存在的 `updatedAt` 晚于 `createdAt` 的记录（旧流水线写入）保持原样，不做批量回填。
