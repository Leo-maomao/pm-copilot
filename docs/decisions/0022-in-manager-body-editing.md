# 管理器内直接编辑需求正文

- 状态：已接受
- 日期：2026-09-14

## 背景

正文此前只能由 pm-copilot 插件的写入工具修改，管理器只开放状态、标题与图示的编辑。整理存量需求（例如清理无用的验收段落）时必须逐个走插件往返，成本高且看不到上下文。

## 决策

在管理器内开放正文编辑，入口是需求卡片右上角的铅笔按钮，位置与状态、图示、删除操作并列。

- 编辑器按段落渲染为等宽文本域，高度跟随内容，不再内部滚动；操作按钮跟在编辑窗口下方，取消不写入。
- 写入范围只有各段落的 `description`：标题、状态、图示与图示归属保持不变。
- 保存复用与插件相同的写入路径，因此正文仍会被规范化（`一、主题` → `### 一、主题`，编号按规则断行）。
- 时间只与创建有关：正文保存与其他管理器写入都不推进时间线，见 [需求时间只与创建有关](./0023-creation-only-timeline.md)。
- 未解锁本机编辑会话时入口不出现，服务端对写入同样返回 403。

## 后果

存量正文可以在阅读位置直接修订，不再需要插件往返。管理器与插件共同维护正文且写入路径一致，但校验深度不同：服务端只校验段落数量和字段类型，不做内容规则校验，因此「正文不写验收标准」一类的写作规则目前在数据层没有强制。需求的时间只反映创建：编辑后目录位置与卡片日期都不变，判断正文是否被改过需要借助文件差异或版本历史。
