# 需求深链

- 状态：已接受
- 日期：2026-09-17

## 背景

需求结果的常用去处是把某一条需求发给研发。此前管理器只有一个入口地址，当前看的是哪条需求只存在浏览器的 sessionStorage 里，无法把位置发给别人；研发也只能自己在一百多条需求里找。

## 决策

- 需求链接固定为 `<origin>/r/<项目目录名>/<需求 ID>`，两段各自做百分号编码。项目目录名即索引里的 `projectName`，需求 ID 即需求 Markdown 里的稳定 `id`。
- 服务端对未知路径返回 `index.html`，由页面自己解析链接；`/api/*` 与 `assets/*` 的 404 保持不变，避免把失效的脚本请求回答成 HTML。
- 页面按链接选中对应项目、把该需求滚到正文区顶部，并在左侧目录里选中它；链接指向的需求不存在时给出提示，其余内容照常显示。
- 地址栏跟随正文区当前阅读的需求（`history.replaceState`，只改当前记录，不堆历史），因此从浏览器地址栏复制即可得到该条需求的链接；需求卡片上另提供「复制链接」按钮。
- 索引响应新增 `lanOrigins`：本机非回环、非链路本地、也非 VPN 隧道占位段（RFC 2544）的 IPv4 组成的 `http://<ip>:<port>` 列表，常见局域网段优先。页面在回环地址下用它拼接对外链接，否则用当前访问来源。

## 后果

链接可以在可信局域网内直接转发，研发打开即落在同一条需求上。管理器监听 `0.0.0.0:57391`，链接里的主机名必须是研发可达的地址，所以回环页面不能使用 `127.0.0.1` 拼接。本机同时存在多张网卡时，只能按常见局域网段排序取第一个，不保证它就是研发可达的那一个，此时以「复制链接」按钮提示里的实际链接为准。
