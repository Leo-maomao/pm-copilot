# 插件需求写入 MCP

- 状态：已接受
- 日期：2026-09-11

## 背景

插件需要从任意目标项目会话中稳定创建、补全和修改集中需求库中的需求。仅靠 Skill 指令会让路径识别、目标唯一性、图片归属与原子写入依赖模型临时执行，难以保证管理器可持续读取。

## 决策

`plugins/pm-copilot` 通过本地 stdio MCP 暴露首次配置、需求上下文读取、纯文本创建、已实现功能补全和正文修改工具。工具从用户本机配置读取产品助理仓库路径，以当前目标项目 Git `origin` 或目录名识别项目归属，并复用 `packages/core` 的 Markdown 解析与生成。

开发类补全和正文修改必须显式提交既有图片路径到唯一内容层级；工具保留图片文件、状态和创建时间，并通过临时文件重命名原子写回。图片替换和排序继续由管理器负责。

## 后果

插件新增一个跨工作区本地接口，工具输入与输出成为兼容契约。未来修改工具名称、输入结构、项目识别或图片归属校验时需要新增决策记录和回归测试。
