# 管理器创建正式需求

- 状态：已接受
- 日期：2026-09-10

## 背景

管理器已能维护已有需求的标题、状态和图示。产品在尚未调用插件时，也需要从管理页创建一条正式需求并立即粘贴图示，且该入口不能绕过本机写入边界。

## 决策

管理页在详情区顶部提供搜索和状态筛选工具栏。新建入口仅在已解锁的浏览器中出现，位于每个已归档项目的目录标题中，因此创建时直接继承该项目归属，不提供项目选择。

服务提供受编辑会话保护的 `POST /api/projects` 与 `POST /api/requirements`。前者创建可被索引的空项目，后者将新需求以 `planning` 状态写入统一需求库的对应项目目录，初始化一个一级内容区，并在响应中返回创建记录的项目与稳定 ID。前端据此打开既有图示编辑器并直接进入标题编辑态，图片仍由人工粘贴并写入同目录 `assets/`。

## 后果

新建需求与插件生成的正式需求使用同一 Markdown 格式、资产路径和局域网只读策略。管理器可创建空项目供尚未归档的来源项目使用；项目名称由产品手动输入，创建后仍需要通过该项目节点新建正式需求。
