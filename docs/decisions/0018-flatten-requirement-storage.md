# 扁平化需求存储路径

- 状态：已接受
- 日期：2026-09-11

## 背景

需求库原先使用 `requirements/projects/<项目>/requirements/<需求>/`。其中的项目仍是需求归属和管理器分组边界，但 `projects` 与项目内的 `requirements` 仅重复表达了目录角色，使本机浏览与手动维护路径变深。

## 决策

正式需求改为保存于 `requirements/<项目>/<需求>/`。服务与插件只读取和写入该结构；管理器的项目创建、重命名、删除与需求创建接口保持不变。现有本机项目目录迁移到需求库根目录，`.manager/` 继续用于编辑会话且不作为项目索引。

## 后果

用户进入 `requirements/` 后可直接看到并管理项目，每个项目下直接列出具体需求。项目仍提供多项目隔离、需求归属和稳定资产键的前缀，未引入额外业务层级。
