# 需求层级与图示归属

- 状态：已接受
- 日期：2026-09-10

## 背景

需求管理器以 Markdown 保存一个可独立推进的一级需求。一个需求有时还需要拆分为多个二级内容，且每项内容的图示必须与其实现说明准确对应。若解析或展示时把图示汇总到一级，研发会无法判断图示对应的具体实现内容。

## 决策

`requirement.md` 文件及其 front matter 表达一级需求。正文中不存在二级标题时，正文与图片均归一级需求；存在二级标题时，每个二级标题和其后的内容区间表达一个二级内容，区间内的正文和图片只归该二级内容。

图片只允许引用同一需求目录的 `assets/` 相对路径。Markdown 解析、历史 HTML 导入与管理页呈现都必须保留该层级归属。无法从历史内容确定二级归属的图片只能保留在一级并标记待人工归属，不得自动猜测。

管理器的图示编辑器允许拖动图示，在同一层内重排或移动到另一层；拖至目标图左半区时插入其前，拖至右半区时插入其后。移动后必须原子写回 Markdown 的图片顺序与归属。每条已有分割线都可移除，也可在该位置插入新的空层后直接粘贴图示。

层级由实现边界、交互目标和状态链决定，不由图片数量决定。每张图片必须归属明确内容，同一内容可包含多张图。来源中已经明确分块时可作为强归属依据，但插件仍须按语义决定是否拆分二级内容。

管理页以统一的左图右文方式呈现带图内容：图示与其所属层级关联，与右侧正文垂直居中，并统一随详情区滚动。一级与二级内容有明确层级分隔；移动端可使用单列呈现。

## 后果

插件生成需求、改写需求和重组需求时必须按此层级输出 Markdown。解析器的数据模型和导入流程必须携带层级与图示归属，不能只返回扁平图片列表。

存量 需求文档 中归属不清的图片需要人工确认，管理器不尝试以内容相似度或图片顺序进行自动分配。未来变更标题层级、图示路径范围或归属规则时，需要新增 ADR。
