# 插件工作流

需求管理器从目标项目中调用，但所有输出均写入产品助理仓库的统一需求库。

## 纯文本需求

用户在目标项目会话中描述 Bug 修复或纯文本需求。插件先澄清，再通过 MCP 在对应项目目录创建正式需求，状态固定为 `defined`。管理器随后可直接索引并展示该需求。

## 已实现功能整理

用户先在目标项目完成开发，再在管理器中为同一项目创建需求并粘贴图示。插件读取当前项目代码并定位唯一的已有需求，使用图示路径将生成的正文归入明确的一级或二级内容。原有图示文件和路径不变，完成后状态变为 `defined`。

模型根据实现边界、交互目标和状态链决定二级内容。每张图必须归属一个明确内容，但一个二级内容可以关联多张同一交互链的图；不得按图片数量机械拆分，也不得把不同实现边界的图文连续堆叠。目标不唯一、没有图示或归属不明确时，插件停止写入并提问。

## 已有需求修改

用户指定需求标题或 ID 后，插件原地更新唯一目标的标题、正文和内容层级。状态、创建时间、图片文件和图片路径保持不变，更新时间刷新。图片替换、删除和拖动只在管理器中完成；目标不唯一或图片归属不明确时不写入。

首次运行时，插件在 `~/.config/pm-copilot/config.json` 保存产品助理仓库路径；后续调用自动使用该位置。MCP 使用当前目标项目 Git `origin` 的仓库名作为项目归属；没有远端时回退当前目录名。
