# 插件工作流

需求管理器从目标项目中调用，但所有输出均写入产品助理仓库的统一需求库。

## 自然语言描述

根据用户描述创建正式需求，生成书面化标题、摘要、正文和内容层级，状态固定为 `defined`。

模型根据实现边界、交互目标和状态链决定二级内容。每张图必须归属一个明确内容，但一个二级内容可以关联多张同一交互链的图；不得按图片数量机械拆分，也不得把不同实现边界的图文连续堆叠。

## 根据代码整理

读取当前仓库代码来解释已完成的前端页面和交互。用户提供本地 URL 或要求验证时才访问运行页面。若有同名收件箱草稿，将人工图示归入明确的内容位置；无法确认时先提问。代码或本地页面中识别到多个独立交互区域时，按区域生成二级内容；同一交互的多个状态图归入同一个内容。

## 已有需求修改

用户指定需求标题或 ID 后，插件原地更新唯一目标。状态与创建时间保持不变，更新时间刷新。目标不唯一时不写入。

首次运行时，插件在 `~/.config/pm-copilot/config.json` 保存产品助理仓库路径；后续调用自动使用该位置。
